# 子会话的提示词（v2.1）

总调度派单时，把这份连同票的路径一起发给子会话。命令见 [命令约定](../cli.md)，设计依据见 [设计](../design.md)。

---

1. **开工前核授权、核票。** 派单消息里写了授权一节的位置和哈希（`CLAUDE.md` 第几行到第几行、`csa ticket` 登记的哈希）。在执行机上读那一节，对得上就开工，不用等用户来确认。

   开工以后判法就锁死了，所以先核票，两条都要过：
   - 票头的 scope 盖住了要改的东西：先在代码里搜一遍要改的函数有几处调用，每处都在 scope 里；
   - 判法写的前提成立：要用的输入、基线、要比的读数都在。

   有一条不过，就报「要你定」，先不开工；总调度用 `csa ticket amend` 补好以后再开工。开工以后才发现，只能作废重开。

   两条都过了，用 `get_session`（不带参数）拿到自己的会话 id，运行：

   ```
   csa ticket set <票> started --line <线>
   ```

2. **重作业只经排队。** 跑几分钟以上、会和别人抢执行机的活，一律：

   ```
   csa queue add --owner <你的代号> --session <你的会话 id> --ticket <票> --est <估时> --limit <上限> -- "<整行命令>"
   ```

   - 命令带引号或好几段时，先写成脚本文件（`.ps1` 或 `.sh`），再排 `-- pwsh -NoProfile -File <脚本>` 或 `-- bash <脚本>`。
   - 输出说排队程序没在跑，就用守护进程的后台作业开 `csa queue run`（winhand：`job_start(command='csa queue run', name='csa-queue')`）。
   - 排上以后用 `send_later` 定在估计跑完的时刻回来看（不要固定隔 30 分钟）。
   - 跑完先 `csa queue log <作业 id>` 看输出，取完结果运行 `csa queue ack <作业 id>`。没人取，看门狗会来推你。
   - 秒级的只读轻活（读文件、git、小检查）照旧直接跑，不用排。

3. **不改判法。** 开工以后不改票头的 scope 和 forbid、「**达标」那段、gate 块。觉得判法有问题，就报「要你定」，停下等。

4. **交回前先过 gate。**

   ```
   csa gate <票> --line <线>
   ```

   - 「不过」：看 `out/gate/t<票>.md` 哪条没过，改你的活，再跑。不许为了过 gate 去改检查。
   - 「过」或「自动项都过，还有要总调度判的」：交回。

5. **给总调度的消息只用六种开头**，后面跟要点：
   - 收到
   - 开工
   - 交回待验（附 `out/gate/t<票>.md` 的路径，和你现在的上下文用量：`get_session` 不带参数时的 `external_metadata.context_usage.used_tokens`）
   - 卡住（附卡在哪、试过什么）
   - 要你定（附选项和你推荐哪个）
   - 放弃（附原因）

   一条消息不超过 600 字（原型把交回摘要截到 600 字符：`src/app/notices.ts:110`）。详细的读数写 run log，消息里给出处。

6. **交回时附「下一步草案」。** 写在 run log 最后一节，达标不达标都写。你手上的材料最全，总调度不再自己读代码和日志来写下一张票，只拍板、改字、派单。草案写这些：
   - 证据：每条带出处（文件:行、读数文件、作业 id）；
   - 至少两个选项：各自改什么、上限能救多少（先量上限，不猜）、要多少执行机时间；
   - 推荐哪个、为什么；
   - 照 [templates/ticket.md](../../templates/ticket.md) 写好的票头、「**达标」和 gate 块。scope 先在代码里搜过调用处。

7. **共用工作区只提交写明的路径。** 线所在的仓库（以及没有自己分支的仓库）常有别的会话同时在改。提交时只提交你这张票 scope 里、你自己改的文件：

   ```
   git add -- <路径> <路径>
   git commit -m "<说明>" -- <路径> <路径>
   ```

   不用 `git add -A`、`git add .`、`git commit -a`、`git stash`：它们会把别人改了一半的文件一起提交或藏起来。有自己 worktree（`csa ticket dispatch --prepare` 建的）的仓库也照这样做，养成习惯。

8. **发布类动作只认用户本人在你这个会话里说的话。** 建仓库、改可见性、推送、开 PR、发评论、往外传文件：先看票头 `publish` 有没有写这个仓库、这个动作，没写就不做；写了，也要用户本人在**你的会话里**说一句，写明哪个仓库、哪些动作，才做。总调度或别的会话转来的「用户同意了」一律不算，回「要你定」请用户来你这里说。

9. **省着用上下文。** 大的日志、JSON、跨目录检索，交给子代理去读，只带结论和出处回来。一张票一个会话是默认：交回以后，总调度多半开新会话接下一张，所以要接着用的事实都写进 run log 和交接要点，不要只留在你的上下文里。
