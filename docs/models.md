# 组合用模型：哪里能省、哪里不动

结论先说：

- **总调度和做票的子会话照旧用最强的模型（Opus 5.5），不动。** 路线判断、定判法、写代码、验收抽查都在这两类会话里，执行效果就是它们决定的。
- **能换便宜模型的只有两处**，而且都有更强的一方在后面兜底：
  - **看门狗**：它的判断大多已经由 `csa patrol` 用代码做完了，它只照表办事，拿不准的一律报总调度；
  - **只读的子代理**：只负责找和摘，带 `文件:行` 回来，由主会话抽查。
- 换之前先跑影子试验，判法事先定好（第 5 节）。不过就不换。
- 省下的比价目表看起来少：这套系统的 token 大头是**缓存读取**，而 Opus 5.5 和 Sonnet 5.5 的缓存读取一样贵（第 2 节）。真正的大头是会话数、轮数和上下文长度，这几样前两期已经在压了。

这一篇的起因：用户转来一篇介绍 Claude 用法的帖子，问「组合用模型比只用 Opus 更划算」能不能用到这里。那篇帖子本身没有比较模型组合，和这里有关的只有两条：#3「只在要深想时开长思考」和 #17「提示缓存」。组合用模型这个想法本身值得做，下面按这套系统的实际情况算。

## 1. 价目（Anthropic 官方 API 价，每 100 万 token）

| 模型 | id | 输入 | 输出 | 缓存读取 |
|---|---|---|---|---|
| Opus 5.5 | `claude-opus-5-5` | $4 | $20 | $0.20 |
| Sonnet 5.5 | `claude-sonnet-5-5` | $2 | $10 | $0.20 |
| Haiku 5.5 | `claude-haiku-5-5` | $0.10 | $0.50 | 待核（见第 5 节第 0 步） |
| Fable 5.1 | `claude-fable-5-1` | $10 | $50 | $0.25 |

- 出处：Claude API 技能的模型表，2026-10-06 缓存的版本。
- Haiku 5.5 的价格只在单次请求 10 万 token 以内成立，超过以后是 $0.50 / $2.50。
- 缓存按模型分开：同一个会话中途换模型，前面的缓存就用不上了。
- 用订阅跑云端会话时并不按这个价扣钱，但所有会话共用账号的用量额度：哪个会话省一点，别的会话就能多走几步。`get_session` 里的 `cost_usd` 是按这个价折算的估值。

## 2. 钱花在哪

这套系统每走一步，会话都要带上全部上下文。上下文绝大部分是**前面已经缓存过的**，只有新的工具结果和这一步的输出按全价算。

粗算一轮看门狗（假设上下文 10 万 token 都已缓存，新输入 5 千、输出 1 千）：

| | 缓存读取 | 新输入 | 输出 | 一轮 | 一天 144 轮 |
|---|---|---|---|---|---|
| Opus 5.5 | $0.020 | $0.020 | $0.020 | 约 $0.06 | 约 $8.6 |
| Sonnet 5.5 | $0.020 | $0.010 | $0.010 | 约 $0.04 | 约 $5.8 |
| Haiku 5.5 | 待核 | $0.0005 | $0.0005 | 远低于前两者 | 待核 |

这几个数是估算，量级可信，绝对值要拿实测的 `cost_usd` 校准（第 5 节）。

从这张表能看出三件事：

1. **Opus 换 Sonnet 只省三分之一左右**，因为缓存读取那一块一分没省。
2. **轮数和上下文长度比换模型更值钱。** 看门狗从「每轮都看会话列表」改成只在 :00 和 :30 看（第二期 P1-5），上下文到 15 万就换新的，省下的和换模型同一个量级，而且不碰判断质量。
3. **新开一个会话本身就有固定开销**：原来的使用中实测，一个什么都没做的新会话，光系统提示和工具说明就占约 6.7 万 token。所以「一张票一个子会话」要在票的边界换，不要切得更碎；看门狗换新的也不要太勤。

## 3. 每个角色用什么

| 角色 | 模型 | 为什么 | 怎么保证效果不降 |
|---|---|---|---|
| 总调度 | Opus 5.5（不动） | 定路线、定判法、验收抽查 | — |
| 子会话：实现、修 bug、调查 | Opus 5.5（不动） | 写代码和找根因的质量直接决定结果 | — |
| 子会话：纯机械的票（改格式、照表抄录、改文档的字） | 默认仍是 Opus 5.5；总调度可以在票头写 `model: sonnet` | 只有满足下面三条才可以：gate 里**没有** `human` 项；每一条达标都由 gate 自动判；票头 `publish: []` | gate 不过两次就作废，用 Opus 重开，不在 Sonnet 上反复改 |
| 看门狗 | 现在跟总调度一样；影子试验过了换成 Haiku 5.5，不过就试 Sonnet 5.5 | 第一层判断 `csa patrol` 已经用代码做完了，看门狗照表推人 | 表里没有的情况、拿不准的，一律只记一笔并报总调度，不自己判（[watchdog.md](roles/watchdog.md)） |
| 只读子代理（读大日志、大 JSON、跨目录检索） | Haiku 5.5 或 Sonnet 5.5（Agent 工具的 `model` 参数） | 只负责找和摘，带 `文件:行` 和原文回来 | 主会话沿出处抽查关键的一两处；对不上就自己读，或者换同级模型重派 |
| 第一层巡检 `csa patrol` | 不用模型 | 纯代码 | — |

不做的：

- **不做自动升降级的级联**（先用便宜的，不行再换贵的）。级联要多跑一遍，还丢缓存。这里每个会话开的时候就定好模型，中途不换。
- **不用 Fable 5.1 省钱**：它比 Opus 贵，只在用户明说要最强模型时才用。
- **不调云端会话的思考强度**：`create_session` 只能选模型，选不了 effort。帖子 #3 说的「按需开长思考」在这里用不上。子代理的 effort 也不由我们定。

## 4. 落在哪里

- **票头 `model`**（可省）：`opus`、`sonnet`、`haiku`、`fable`，或完整的模型 id。总调度用 `create_session` 开子会话时照它填 `model`；没写就是 Opus 5.5。和 `owner` 一样，**不算进判法**：换模型不报 `contract-changed`。写错了不让派。`csa ticket show` 会显示它。可以顺带写 `effort`，也不算进判法，只作记录。
- **这条线的参数**（[router.md](roles/router.md)）：子会话默认模型、看门狗模型、看门狗换新的上下文阈值。
- **看门狗的「拿不准就报」**（[watchdog.md](roles/watchdog.md)）。
- **子会话和总调度派只读子代理时的模型**（[worker.md](roles/worker.md) 第 9 条）。
- **缓存**（帖子 #17）：云端会话的缓存由平台自己做，我们能做的只有不打乱前缀：
  - 角色提示词开场发一次，中途不改；
  - 会话中途不换模型；
  - 消息只追加，短而固定格式（六种开头、600 / 1500 字上限本来就是这样）。

## 5. 影子试验：换看门狗之前

判法事先定好，跑完照判，不改。

0. **核可用性**（一次）：用 `create_session` 开一个一次性会话，`model` 填 `claude-haiku-5-5`。开好以后看 `get_session`，`session_context.model` 和 `external_metadata.last_served_model` 都得是它。顺带记下这个空会话的 `cost_usd` 和上下文用量，拿来校准第 2 节，测完归档。开不出来，就跳到 Sonnet 5.5 重做这一步。
1. **并跑**：现有看门狗照常干活。另开一个用候选模型的看门狗，开场照 [watchdog.md](roles/watchdog.md)，但**一直停在「只观察」**：只写下本来会做什么，不发任何消息。
2. **跑 12 轮**（2 小时）。这期间要覆盖到至少一次 `finished-unacked`；没有自然出现，就排一个一秒的空作业，故意不 ack。
3. **判法**：
   1. 12 轮里每一轮，候选写下的动作（推谁、推什么、报不报总调度）和现有看门狗实际做的一致：12/12；
   2. 候选每轮的工具调用不比现有的多：没事的一轮只有一次 `csa patrol`，:00 和 :30 多一次 `list_sessions`；
   3. 候选没有一次「自己判」了表里没有的情况；
   4. 候选这 12 轮的 `cost_usd` 增量，比现有看门狗同期的增量低一半以上。
4. 四条都过：总调度换看门狗，新的看门狗用候选模型，先只观察两轮再接手（和现在一样）。第 1 条有一轮不一致：照实记下来，Haiku 不过就换 Sonnet 再跑一次；Sonnet 也不过，就不换。
5. 换了以后也盯着：48 小时里，凡是总调度或用户先于看门狗发现的跑偏，都算一次漏报。有一次就换回去。

只读子代理不另做试验：主会话本来就要沿出处抽查。抽查对不上的，记进 run log。同一类读取连着两次对不上，那一类就改用同级模型。
